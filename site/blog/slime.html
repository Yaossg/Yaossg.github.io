如何快速寻找史莱姆区块？

October 16, 2026 · 44 min read

在 Minecraft 中，xzxzxz 平面上每 16×1616 \times 1616×16 个方块的区域被称为一个区块。有一些区块在 y<40y<40y<40 的地方可以自然生成史莱姆，被称为史莱姆区块。

史莱姆区块是史莱姆农场的基础。为了效率最大化，史莱姆农场往往会在史莱姆区块密集的地方选址。例如 3×33 \times 33×3、4×44 \times 44×4 甚至 5×55 \times 55×5 的相邻史莱姆区块。此外还有人想要寻找特定图案的史莱姆区块。

本文主要介绍 Java 版史莱姆区块的生成规律和如何快速寻找特定图案的史莱姆区块。

史莱姆区块的判定​

史莱姆公式​

史莱姆区块的判定由世界种子 www 和区块坐标 (x,z)(x,z)(x,z) 共同决定，相同的种子与坐标总是会得到相同的结果：先计算坐标项 T(x,z)T(x,z)T(x,z)，与世界种子组合后初始化 Random，再调用 nextInt(10)。返回 0 就是史莱姆区块，返回 1 到 9 则不是。也就是说，史莱姆区块的概率是 1/101/101/10。

    return new Random(
        worldSeed
        + (int) (x * x * 4987142)

Random 的内部实现​

下面的函数等价于 new Random(randomSeed).nextInt(10)： 初始化得到 48 位状态 uuu；每次乘 AAA、加 11、保留低 48 位得到 vvv，再取高 31 位得到 qqq。通常返回 q % 10；若 q - value + 9 超过有符号 32 位整数的上限，就从当前状态继续重抽。

int nextInt10(long randomSeed) {
    final long A = 0x5DEECE66DL;
    final long mask48 = (1L << 48) - 1;
    long u = (randomSeed ^ A) & mask48;

    while (true) {
        long v = (A * u + 11) & mask48;
        int q = (int) (v >>> 17);
        int value = q % 10;
        if ((long) q - value + 9 <= 0x7FFFFFFFL) {
            return value;
        }
        u = v;
    }
}

朴素的爆搜​

我们暂时把 Random 的数学性质按下不表，基于上面的公式，采用朴素的手段进行爆搜。

CPU：按种子枚举位置​

最直接的方法是枚举世界种子和区块坐标，调用上面的判定函数。要找一片全部满足要求的区域，就检查该位置及其周围各格；只要一格失败，这个候选便可提前退出：

for worldSeed in seeds:
    for (x, z) in positions:
        allSlime = True
        for (dx, dz) in requiredOffsets:
            if not isSlimeChunk(worldSeed, x + dx, z + dz):
                allSlime = False
                break
        if allSlime:
            record(worldSeed, x, z)

requiredOffsets 列出待检查区域内各格相对 (x, z) 的偏移。break 只结束当前区域的逐格检查，随后继续检查下一个位置。

CPU 多线程把种子区间分给不同工作线程。每个线程拿到一批种子，逐个扫描同一张坐标地图；不同候选之间互不依赖，适合并行处理。

这一步的主要成本是候选太多。即使绝大多数候选在前几格就失败，也仍要逐个访问“种子数 × 位置数”这么多种组合。

第一版 CUDA 保留上面的循环结构，让一个 GPU 线程负责一个种子，在线程内部扫描整个坐标矩形：

GPU 可以同时安排大量这样的任务。这里的 thread 是执行一份任务的线程，block 是一组线程，kernel 是 GPU 执行的函数。把种子分给更多线程，便能同时检查更多候选。

拒绝采样的原因​

nextInt(10) 不能直接把 next(31) 的结果对 10 取模，因为 2312^{31}231 不是 10 的整数倍：

231=10×214748364+8.2^{31}=10\times214748364+8.231=10×214748364+8.

在 0,…,231−10,\ldots,2^{31}-10,…,231−1 中，余数 0 到 7 各出现 214748365214748365214748365 次，而余数 8 和 9 各出现 214748364214748364214748364 次。直接取模会让前八个结果略微偏多。为消除这种取模偏差，Java 会拒绝末尾多出来的 8 个数，再从当前状态继续生成下一个数。这就是官方文档中 nextInt 的拒绝采样。

因此，前面代码中的溢出检查，等价于判断 qqq 是否落入拒绝区间：

本文后续算法的局限性​

在后续的数学性质分析中，我们只考虑首次输出的情况。这会造成两种情况：

  • 误报（false positive）：首次输出落入拒绝区间，且能被 10 整除，但重抽结果不能被 10 整除。只检查首次输出会将它误判为史莱姆区块。
    • 这个问题很容易解决：在搜索到候选后，用完整的算法验证一次，即可排除误判。
  • 漏报（false negative）：首次输出落入拒绝区间，且不能被 10 整除，但重抽结果能被 10 整除。只检查首次输出会漏掉这个史莱姆区块。
    • 这个问题很难解决：要考虑重抽的情况，必须在搜索算法里增加一个判断和分支，这会显著降低算法的性能。

不过考虑到概率极小，漏掉的史莱姆区块数量很少。后文的算法都是基于首次输出的情况，辅以完整验证来排除误报。

反推种子算法​

在固定坐标的情况下，要想寻找到满足条件的世界种子，最直接的办法是枚举所有可能的 www，计算 qqq，检查是否满足条件。
